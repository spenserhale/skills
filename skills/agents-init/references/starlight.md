# Starlight site over `docs/`

Render the repo's `docs/` folder as a browsable site without moving or copying a file. `docs/` stays the source of truth; the Astro project in `site/` only renders it. Verified end to end with Starlight 0.42.7, Astro 7.2.10, astro-rehype-relative-markdown-links 0.19.2, and @astrojs/markdown-remark 7.3.4.

## Steps

1. **Create the project** in `site/` (in a monorepo, `apps/docs/`, with one more `../` in the symlink below). Use the repo's package manager if it is not npm:

   ```bash
   npm create astro@latest site -- --template starlight --install --no-git --yes
   ```

   The template ships its own `site/.gitignore` and a `site/AGENTS.md` with Astro dev-server guidance. Keep both; the nested `AGENTS.md` applies only inside `site/`.

2. **Point the docs collection at the repo's `docs/`** by replacing the sample content with a symlink:

   ```bash
   rm -rf site/src/content/docs
   ln -s ../../../docs site/src/content/docs
   ```

   Keep `site/src/content.config.ts` as generated (`docsLoader()` with `docsSchema()`). Do not switch to Astro's `glob()` loader with `base: '../docs'`: it builds, but autogenerated sidebar groups come out empty because Starlight resolves sidebar directories against `src/content/docs`.

3. **Sidebar**: one group per folder in `site/astro.config.mjs`. Starlight 0.39 and later reject `autogenerate` directly on a labeled group; nest it in `items`:

   ```js
   sidebar: [
     { label: 'Product', items: [{ autogenerate: { directory: 'product' } }] },
     { label: 'Specs', items: [{ autogenerate: { directory: 'specs' } }] },
     { label: 'Decisions', items: [{ autogenerate: { directory: 'decisions' } }] },
     { label: 'Plans', items: [{ autogenerate: { directory: 'plans' } }] },
     { label: 'Guides', items: [{ autogenerate: { directory: 'guides' } }] },
   ],
   ```

   Drop groups for folders that do not exist; an empty group renders as a dead heading.

4. **Make relative `.md` links work on the site.** Starlight leaves `../decisions/0007-x.md` as written, which 404s. Astro 7 also needs the remark processor installed before any rehype plugin runs:

   ```bash
   cd site && npm install astro-rehype-relative-markdown-links @astrojs/markdown-remark
   ```

   ```js
   // site/astro.config.mjs
   import relativeLinks from 'astro-rehype-relative-markdown-links';

   export default defineConfig({
     markdown: {
       rehypePlugins: [[relativeLinks, { collectionBase: false, trailingSlash: 'always' }]],
     },
     integrations: [starlight({ /* title, sidebar */ })],
   });
   ```

   Links keep their anchors: `../plans/2026-10-25-x.md#tasks` becomes `/plans/2026-10-25-x/#tasks`.

5. **Build once to prove it**: `cd site && npm run build` exits 0 and `site/dist/` holds one page per doc. A doc without `title` frontmatter fails with `title: Required`; fix the doc, not the schema. Records written before this structure (a Nygard-style ADR with a body H1) get a `title` added and their H1 removed: a format-only edit that leaves the decision's text alone.

6. **Record it**: carry the commands into `AGENTS.md` Quick start when you write it (`cd site && npm run dev`, `cd site && npm run build`), with the note "`docs/` is the source; `site/` only renders it", and make decision 0001 say the site exists.

## Behavior to expect

- `_template.md` files and any other `_`-prefixed file are skipped.
- `docs/index.md` is the home page; `docs/README.md`, if present, becomes `/readme/`.
- Unknown frontmatter keys (`status`, `date`, `decision-makers`) pass through without schema changes. Extend `docsSchema()` only to render them.
- `lastUpdated: true` shows nothing: git cannot follow a path through the symlink. Leave it off, or set a `lastUpdated: YYYY-MM-DD` date in a page's frontmatter.

## Windows

Git checks symlinks out as plain files unless symlinks are enabled (Developer Mode, `git config core.symlinks true`). Without them, use Astro's `glob()` loader with `base: '../docs'` in `site/src/content.config.ts` and list sidebar entries by slug (`{ label: 'Billing', slug: 'specs/billing' }`) instead of autogenerating them. In that setup the link plugin cannot map paths (it expects `src/content/docs`), so relative `.md` links stay unrewritten on the site; enabling symlinks is the better fix.

## Deploying

Publishing the site is an outward-facing step. Leave it out unless the user asks; then follow the Starlight deployment guide for their host.
