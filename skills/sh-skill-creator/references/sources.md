# Sources

What each contributed to the rule set. Research current as of September 2026; the rules stand on their own once the sources move.

## Specification and official guides

- **Agent Skills specification** (agentskills.io/specification). The portable format: folder layout, `name` and `description` constraints, `license`, `compatibility`, `metadata`, `allowed-tools`, the three-layer loading model, one-level references, `skills-ref validate`. The validator enforces these.
- **Claude Code skills docs** (code.claude.com/docs/en/skills). The Claude-only frontmatter (`disable-model-invocation`, `user-invocable`, `argument-hint`, `arguments`, `context`, `agent`, `paths`, `hooks`, `when_to_use`), string substitutions, dynamic `!` commands, synced-skill restrictions, compaction budget (5,000 tokens per skill, 25,000 total), the 1,536-char combined listing cap.
- **Anthropic skill authoring best practices** (platform.claude.com). Degrees of freedom, third-person descriptions, gerund naming, under 500 lines, one-level references, TOC over 100 lines, feedback loops, "solve don't defer" for scripts, no voodoo constants, fully qualified MCP tool names, the pre-share checklist, evaluation-driven development with a Claude A / Claude B loop.
- **Anthropic skill-creator** (github.com/anthropics/skills). The eval-driven loop: with-versus-without runs spawned together, expectations drafted while runs execute, timing captured from notifications, grading with `text`/`passed`/`evidence`, benchmark aggregation, blind comparison, description optimization with a 60/40 train/test split. "Pushy" descriptions to counter under-triggering. Caps MUST/ALWAYS as a yellow flag. Evals format adopted here for compatibility.
- **Lessons from building Claude Code: how we use skills** (Anthropic blog, June 2026). Nine internal categories; skills that straddle categories confuse the agent; skills are folders not markdown files; gotchas as the highest-signal section; "state the goal and the constraints, not every step"; verification skills had the most measurable impact.
- **The Complete Guide to Building Skills for Claude** (Anthropic PDF). Three kinds of testing: triggering, functional, performance comparison.
- **Anthropic: Demystifying evals for AI agents.** Start with roughly 20 to 50 real tasks or failures, then expand.
- **Anthropic: Effective context engineering.** Smallest high-signal context beats exhaustive instructions.
- **OpenAI skill-creator** (github.com/openai/skills, now deprecated in favor of openai/plugins). "Include all when-to-use information in the description, not the body"; information lives in SKILL.md or references, never both; grep patterns for references over 10k words; no README/CHANGELOG inside a skill; `agents/openai.yaml` schema (`interface.display_name`, `short_description` 25 to 64 chars, `default_prompt`, `dependencies.tools`, `policy.allow_implicit_invocation`); scaffold-then-validate workflow.

## Community

- **Matt Pocock, mattpocock/skills.** User-invoked versus model-invoked as the first design decision; a user-invoked skill may call model-invoked skills but never another user-invoked one; thin user-invoked wrappers over model-invoked discipline; human-facing one-line descriptions for user-invoked skills; front-load the leading word, one trigger per branch, cut identity the body carries; per-repo config in `docs/agents/*.md` written by a setup skill and read at run time, with skills speaking in abstract verbs that the config translates; hard versus soft config dependency; invoke siblings by name not by file link; positive phrasing over prohibition; prune sediment and sprawl by deleting whole sentences; a router skill that must be re-synced whenever a routed skill changes.
- **Jesse Vincent, obra/superpowers, `writing-skills`.** Skill authoring as RED-GREEN-REFACTOR: baseline without the skill, write against the observed rationalizations, close loopholes; pressure scenarios combining three or more pressures; the meta-test question when a skill fails; descriptions that summarize the workflow become shortcuts the agent takes; "if it is enforceable with regex or validation, automate it, save documentation for judgment calls"; match the form to the failure (prohibition plus rationalization table for rule-skipping, positive recipe for wrong-shape output, structural slot for omissions, conditional for context-dependent behavior); no nuance clauses; searchable symptoms and error strings in the body; the Cialdini persuasion findings, used sparingly and only where they serve the user.
- **Addy Osmani, agent-skills; Vercel Labs, agent-skills; Emil Kowalski, skills.** Expert guidance expressed as decision rules and recognizable anti-patterns rather than "write good code"; taste encoded as constraints and trusted defaults, not checklists.
- **Peter Bakaus, Impeccable.** A skill grown into a tested product: routed reference playbooks, deterministic static checks, tool-call-trace assertions, cross-provider behavior testing, one canonical source compiled per harness.

## Research

- **SkillsBench** (arXiv 2602.12670). Curated skills raised average pass rate from 33.9% to 50.5% across 18 model-harness configurations; focused skills with at most three modules beat larger bundles; self-generated skills gave no benefit; some tasks showed negative deltas. Harness: benchflow-ai/skillsbench.
- **SWE-Skills-Bench** (arXiv 2603.15401). Small average improvement across public software-engineering skills; 39 of 49 produced no pass-rate improvement. Prose quality and stars predict nothing.
- **Agent Skills in the Wild** (arXiv 2601.10338). At least one vulnerability in 26.1% of studied skills. A 2026 industry audit found prompt injection in 36% of tested skills.
- **Meincke et al. 2025**, persuasion principles in LLM compliance (N = 28,000). Authority, commitment, and social proof raise compliance; the reason this skill prefers explained rules over caps is that explanation generalizes and shouting does not.
